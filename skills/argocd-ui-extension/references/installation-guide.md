# Install and establish real integration

After local validation, deliver the archive and hashes for review. Deployment is a separate explicitly requested action; do not install into a cluster, publish or push by default. See the official [UI extension installation guide](https://argo-cd.readthedocs.io/en/stable/developer-guide/extensions/ui-extensions/); verify manifests against the exact release and actual deployment.

The package contains resources/extension-name.js. Argo CD reads UI JavaScript from /tmp/extensions in argocd-server. Arrange a shared volume and an init container (or the environment's existing installer) that places the script there, with a pinned installer image/digest chosen for that environment. Account for all server replicas, existing extension files and deployment volume mounts. There is no audited server.enable.ui.extensions setting in these contracts. A backend proxy is separate: verify its release-specific enable-proxy-extension flag and service configuration; backend.kind:proxy does not deploy one.

Verify the exact server image/tag, the served extension JS/hash, absence of bundled React, successful method registration and actual rendering for the chosen profile. Exercise context fallback, shouldDisplay application handling, flyout open/close and requested domain UI. Record target version, deployed bundle/package hashes, deployment method and observations as separate integration evidence. Only those exact tested artifacts may add that exact version to an integrated matrix. Local validate always reports integration not-run and releaseComplete:false.
